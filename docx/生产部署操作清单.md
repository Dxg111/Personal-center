## 3. 服务器初始化

SSH 登录：

```bash
ssh root@124.220.190.172
```

> ⚠️ 腾讯云 Ubuntu 镜像**默认禁用 root 密码登录**，这一步很可能直接失败：
> `root@124.220.190.172: Permission denied (publickey,password)`。
> 进 root 的两种办法：
> 1. **控制台网页终端（推荐）**：云服务器 → 实例 → 登录 → OrcaTerm，进去即是 root，无需密码；
> 2. 控制台「更多 → 密码/密钥 → 重置密码」设置 root 密码后重新登录（需重启实例）。

### 3.1 安装 Docker

- [ ] 卸载可能残留的旧版本
      ```bash
      sudo apt remove -y docker docker-engine docker.io containerd runc 2>/dev/null || true
      ```
- [ ] 配置官方源并安装
      ```bash
      sudo apt update && sudo apt install -y ca-certificates curl gnupg
      sudo install -m 0755 -d /etc/apt/keyrings
      curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
      sudo chmod a+r /etc/apt/keyrings/docker.gpg
      echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
        | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
      sudo apt update
      sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
      sudo systemctl enable --now docker
      ```
- [ ] **配置镜像加速（大陆节点必做）**

      不配的话，`docker compose build` 会在拉基础镜像时直接超时：
      `failed to resolve source metadata for docker.io/library/python:3.11-slim: dial tcp ... i/o timeout`

      ```bash
      sudo mkdir -p /etc/docker
      sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
      {
        "registry-mirrors": [
          "https://mirror.ccs.tencentyun.com",
          "https://docker.m.daocloud.io"
        ]
      }
      EOF

      sudo systemctl daemon-reload
      sudo systemctl restart docker
      docker info | grep -A4 "Registry Mirrors"
      ```

- [ ] 测速确认源可用（顺带排查哪些已失效）
      ```bash
      for m in mirror.ccs.tencentyun.com docker.m.daocloud.io docker.1panel.live hub.rat.dev dockerproxy.net; do
        printf '%-32s ' "$m"
        curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' --max-time 8 "https://$m/v2/" || echo fail
      done
      ```
      判断：`200` / `401` / `404` 都算**可达**（`/v2/` 要求认证，401 正常），`000` 才是超时不可用。
      把可用的写进 `daemon.json`，按顺序回退。
      > `mirror.ccs.tencentyun.com` 是腾讯云内网地址，只有腾讯云 CVM 能用；换机器要重配。

- [ ] 验证
      ```bash
      docker --version
      docker compose version    # 必须是 v2.x，不能是 docker-compose v1
      ```
- [ ] 确认 `docker compose version` 输出以 `v2.` 开头（v1 已停止维护，不能用）
- [ ] `docker info` 中 Registry Mirrors 列表非空
- [ ] 单独测一次拉取：`docker pull python:3.11-slim`

### 3.2 添加 Swap（2G 内存必做，前端构建会 OOM）

- [ ] 创建 2GB swap
      ```bash
      sudo fallocate -l 2G /swapfile
      sudo chmod 600 /swapfile
      sudo mkswap /swapfile
      sudo swapon /swapfile
      echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
      ```
- [ ] 验证 `free -h` 中 Swap 行 ≥ 2.0Gi

> `free` 显示 Swap 为 0 时立刻停下处理，否则 `docker compose build` 很可能被 OOM Killer 杀掉。

### 3.3 防火墙

- [ ] 只开放 SSH / HTTP / HTTPS
      ```bash
      sudo ufw allow 22/tcp
      sudo ufw allow 80/tcp
      sudo ufw allow 443/tcp
      sudo ufw enable
      sudo ufw status verbose
      ```
- [ ] 确认状态为 `active`，规则只有 22/80/443

### 3.4 创建部署用户

- [ ] 建用户，**同时加入 `sudo` 和 `docker` 两组**
      ```bash
      sudo adduser deploy
      sudo usermod -aG sudo   deploy
      sudo usermod -aG docker deploy
      ```
      > 只加 `docker` 不加 `sudo`，后面每一步 `sudo` 都会失败并报
      > `deploy is not in the sudoers file. This incident will be reported.`
- [ ] **退出并重新登录**（附加组只在新会话生效）
      ```bash
      exit
      ssh deploy@124.220.190.172
      groups              # 必须同时包含 sudo 和 docker
      sudo -v             # 能通过即正常
      ```
- [ ] 新开一个终端验证能免 sudo 跑 docker
      ```bash
      docker ps
      ```
- [ ] 把本地公钥写入 `deploy` 的 `~/.ssh/authorized_keys`，并 `chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys`

### 3.5 基础系统设置

- [ ] 时区（Compose 已注入 `TZ=Asia/Shanghai`，宿主机也统一）
      ```bash
      sudo timedatectl set-timezone Asia/Shanghai
      timedatectl
      ```
- [ ] 系统更新并开启自动安全更新
      ```bash
      sudo apt update && sudo apt upgrade -y
      sudo apt install -y unattended-upgrades
      ```
- [ ] （建议）SSH 禁用 root 密码登录
      ```bash
      # /etc/ssh/sshd_config
      # PermitRootLogin no
      # PasswordAuthentication no
      sudo systemctl restart ssh
      ```
      > 改之前先确认 deploy 用户密钥登录成功，否则会把自己锁在外面。

**阶段验收**

- [ ] `docker ps` 用 deploy 用户可直接执行
- [ ] `groups` 同时包含 `sudo` 和 `docker`
- [ ] `sudo -v` 不报 `not in the sudoers file`
- [ ] `docker info` 的 Registry Mirrors 非空
- [ ] `free -h` 有 2G swap
- [ ] `ufw status` 仅 22/80/443
- [ ] `timedatectl` 显示 `Asia/Shanghai`

## 4. 代码上线

代码仓库：`https://github.com/Dxg111/Personal-center.git`（分支 `master`，**私有仓库**）

> 私有仓库意味着：服务器不能匿名拉取，**必须先配鉴权**（4.2），否则 `git clone` 会卡在 `could not read Username`。

### 4.1 先测服务器能不能访问 GitHub

大陆节点直连 GitHub 经常超时，**先测再 clone**，避免卡在那里等半天：

- [ ] 连通性测试（最多等 15 秒）
      ```bash
      curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" --max-time 15 https://github.com
      ```

- [ ] 输出 `200` 且耗时几秒内 → 网络可达，继续 4.2
- [ ] 输出 `000`（超时）/ 卡住 → 直接看 4.4 换通道，不要反复重试

### 4.2 配 Git 鉴权（私有仓库必做）

三种方式选一种。**A 最安全**，token 不会落进 `.git/config`，且只能读这一个仓库。

**A：Deploy Key（推荐）**

- [x] 在服务器上生成专用密钥（`deploy` 用户执行）
      ```bash
      ssh-keygen -t ed25519 -C "deploy@124.220.190.172" -f ~/.ssh/github_deploy -N ""
      cat ~/.ssh/github_deploy.pub
      ```
- [x] GitHub 仓库 → Settings → **Deploy keys** → Add deploy key
      - Title：`vps-124.220.190.172`
          - Key：粘贴上一步输出
          - **不要勾** `Allow write access`（只读即可）
- [x] 配置 GitHub 走 443 端口（大陆 22 端口常被封）
      ```bash
      cat >> ~/.ssh/config <<'EOF'
      Host github.com
        HostName ssh.github.com
        Port 443
        User git
        IdentityFile ~/.ssh/github_deploy
        IdentitiesOnly yes
      EOF
      chmod 600 ~/.ssh/config
      ```
- [x] 验证
      ```bash
      ssh -T git@github.com
      ```
  ​    成功输出：`Hi Dxg111/Personal-center! You've successfully authenticated, but GitHub does not provide shell access.`

**B：Personal Access Token（最快，但会留痕）**

- [ ] GitHub → Settings → Developer settings → Personal access tokens → 生成 token，勾选 `repo` 读权限
- [ ] clone 时带上 token
      ```bash
      git clone https://Dxg111:<TOKEN>@github.com/Dxg111/Personal-center.git /opt/personal-center
      ```
- [ ] clone 完把 token 从远端地址里去掉（否则明文留在 `.git/config`）
      ```bash
      cd /opt/personal-center
      git remote set-url origin https://github.com/Dxg111/Personal-center.git
      git remote -v
      ```
      > 之后 `git pull` 会再次要求输入：用户名填 `Dxg111`，密码填 token。
      > 想免输入可 `git config --global credential.helper store`，但 token 会明文存 `~/.git-credentials`，仅在自己独占的服务器上可接受。

**C：Gitee 镜像（大陆最稳）**

- [ ] Gitee → 新建仓库 →「导入已有仓库」，导入时按提示填 GitHub 凭据/token（私有库必须给）
- [ ] 之后从 Gitee 拉取，服务器只需 Gitee 账号密码或公开仓库直接拉
- [ ] 注意：Gitee 只是镜像，**更新时先在 Gitee 点「同步源仓库」**，否则 `git pull` 拉不到新提交

### 4.3 clone 代码（主路径）

用 `deploy` 用户操作，避免仓库文件属主变成 root：

- [ ] 创建目录并 clone（用 4.2 里配好的方式）
      ```bash
      sudo install -d -o deploy -g deploy /opt/personal-center
      su - deploy
      ```
  
      # 配了 Deploy Key → 用 SSH 地址
      git clone git@github.com:Dxg111/Personal-center.git /opt/personal-center
      
      # 或者：用 HTTPS（PAT 方式，按 4.2-B 的写法带 token）
      # git clone https://Dxg111:<TOKEN>@github.com/Dxg111/Personal-center.git /opt/personal-center
      
      cd /opt/personal-center
      ```
- [ ] 确认落在预期 commit 上
      ```bash
      git log --oneline -1
      git rev-parse master
      ```
      应与阶段 0 本地 `git rev-parse master` 的输出一致。
- [ ] 确认关键文件齐全
      ```bash
      ls docker-compose.yml docker-compose.env.example backend/Dockerfile \
         backend/init_db.py frontend/Dockerfile frontend/nginx.conf
      ```
- [ ] 确认目录属主是 `deploy`
      ```bash
      ls -ld /opt/personal-center
      ```

> 用完整 clone，不要加 `--depth 1`。第 11 节回滚需要切到旧 tag/commit，浅克隆拿不到历史。

### 4.4 网络不可达时换通道

（若 4.1 已确认可达，本节跳过；4.2 的鉴权方式仍然需要。）

按推荐顺序，选一个即可：

**通道 A：Gitee 镜像（大陆最稳，推荐）**

直接按 4.2-C 做：Gitee 导入私有仓库 → 在服务器 clone Gitee 地址。
代价是更新流程多一步「先在 Gitee 点同步源仓库」。

**通道 B：SSH over 443（GitHub 的 HTTPS 被限速但 443 端口本身通）**

4.2-A 的 `~/.ssh/config` 已经让 `github.com` 走 `ssh.github.com:443`，所以配好 Deploy Key 后，
直接把 clone 地址从 `https://...` 换成 `git@github.com:...` 往往就能通：

```bash
ssh -T git@github.com                     # 先确认认证与网络都 OK
git clone git@github.com:Dxg111/Personal-center.git /opt/personal-center
```

**通道 C：走代理（服务器有可用出口时）**

```bash
git config --global http.proxy  http://<代理地址>:<端口>
git config --global https.proxy http://<代理地址>:<端口>
git clone https://github.com/Dxg111/Personal-center.git /opt/personal-center
# 结束后建议清掉，避免后续 pip/npm 请求也被代理
git config --global --unset http.proxy
git config --global --unset https.proxy
```

**通道 D：本地打包上传（兜底）**

```powershell
# 本地 Windows
cd E:\code\Personal-center
git archive --format=tar.gz -o deploy.tar.gz HEAD
scp deploy.tar.gz deploy@124.220.190.172:/tmp/
```

```bash
# 服务器
sudo install -d -o deploy -g deploy /opt/personal-center
tar xzf /tmp/deploy.tar.gz -C /opt/personal-center
rm /tmp/deploy.tar.gz
cd /opt/personal-center && ls -a
```

> ⚠️ 不要用 ghproxy 这类第三方加速域名拉生产代码：中间人可以替换源码，而你无法察觉。若确实用了，克隆后必须核对 `git rev-parse HEAD` 是否等于你本地发布的 commit hash；无法核对就不要部署。

**阶段验收**

- [ ] `/opt/personal-center` 内有 `docker-compose.yml`、`backend/`、`frontend/`
- [ ] `git rev-parse master` 与本地一致
- [ ] 目录属主是 `deploy`（`ls -ld /opt/personal-center`）

## 6. 构建与首次启动

- [x] 检查 80 端口没被占用
      ```bash
      sudo ss -lntp | grep ':80 ' || echo "80 空闲"
      ```
      若被宿主机 nginx/apache 占用：`sudo systemctl stop nginx apache2` 并 `sudo systemctl disable nginx apache2`，或改用 Caddy 反代方案。

- [ ] 构建镜像（首次约 10~40 分钟，之后有缓存约 1~3 分钟）
      ```bash
      cd /opt/personal-center
      docker compose build
      ```

      构建期间可能出现的慢点与对策：

      | 阶段 | 正常耗时 | 说明 |
      |---|---|---|

## 附录 B：故障速查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 浏览器打不开，本地 curl 超时 | 腾讯云安全组未放行 80 | 回第 2 节 |
| `bind: address already in use` | 宿主机 nginx/apache 占用 80 | `sudo ss -lntp \| grep ':80 '` → 停掉占用进程 |
| 页面 502 | backend 未启动或不健康 | `docker compose logs backend`；`docker compose exec backend curl -f localhost:8000/health` |
| MySQL unhealthy | 密码与 volume 初始化的不一致 | 首次部署可 `down -v` 重来；已有数据则用原密码或改 `ALTER USER` |
| 上传 413 | Nginx `client_max_body_size` 太小 | 确认 `frontend/nginx.conf` 为 `6m` 并重建 frontend |
| 图片 404 | `/static/` 未反代或被正则拦截 | 确认 `location ^~ /static/`；`ls /app/uploads` |
| `failed to resolve source metadata for docker.io/library/... i/o timeout` | Docker Hub 不可达 | 按 3.1 配镜像加速，`docker info \| grep -A4 "Registry Mirrors"` 确认 |
| `pip ... ReadTimeoutError: files.pythonhosted.org` | pypi 直连太慢（常见 8~12 kB/s） | 确认 `backend/Dockerfile` 含 `PIP_INDEX_URL`（commit `0a2143e` 起），`git pull` 后重建 |
| `Could not find a version that satisfies the requirement xxx (from versions: none)` | **通常是索引/轮子下载超时，不是版本不存在** | 别改版本号，先换国内 pip 源重试 |
| `deploy is not in the sudoers file` | 未加入 sudo 组 | root 执行 `usermod -aG sudo deploy`，**重新登录**后再试 |
| `ssh root@IP` → `Permission denied (publickey,password)` | 腾讯云默认禁用 root 密码登录 | 用控制台 OrcaTerm 网页终端；或控制台重置 root 密码 |
| polkit `pam_authenticate failed` | 该用户没有密码（纯密钥登录的镜像常见） | root 进去后 `passwd <用户>` 设密码，或用 root 直接操作 |
| `apt-get install` 卡十几分钟 | 基础镜像 Debian 源慢 | 成功一次即进缓存；彻底重建时可改 `mirrors.tencentyun.com` |
| npm `ECONNRESET` | 构建走官方源不稳定 | `.env` 设 `NPM_REGISTRY=https://registry.npmmirror.com` 后 `build --no-cache frontend` |
| `vite: not found` | 只装了生产依赖 | 确认 Dockerfile 用 `npm ci`（不加 `--omit=dev`） |
| 构建被 Killed | 内存不足 | 检查 swap；或在本地构建后 `docker save/load` 上传 |
| `git clone` 一直卡住/超时 | 大陆节点直连 GitHub 被限速 | 先按 4.1 测连通性；改走 4.4 的 Gitee / SSH 443 / 代理 |
| `could not read Username for 'https://github.com'` | 私有仓库未配鉴权 | 按 4.2 配 Deploy Key 或 PAT |
| `Permission denied (publickey)` | Deploy Key 未加进 GitHub，或 `ssh.github.com:443` 未配 | 检查 4.2-A 的 `~/.ssh/config` 与仓库 Deploy keys |
| `git clone` 报 `Could not resolve host` | DNS 解析失败 | 换 DNS：`echo "nameserver 223.5.5.5" \| sudo tee /etc/resolv.conf` 后重试 |
| Gitee 上 `git pull` 没新提交 | 只是镜像仓库，未同步源仓库 | Gitee 仓库页点「同步源仓库」后再拉 |
| CORS 报错 | `PUBLIC_ORIGIN` / `CORS_ORIGINS` 不对 | 改为 `http://124.220.190.172`，`docker compose up -d` 重建 backend |
| 登录 200 但后续接口 401 | token 未带上 / `SECRET_KEY` 变了 | 清浏览器 localStorage 重登；确认 `SECRET_KEY` 未被改动 |
| 管理员密码忘了 | — | 服务器上重跑初始化或用 Python 脚本重置 `admin_user.password_hash` |
